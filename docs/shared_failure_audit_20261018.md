# 多版本共同失败链路审查：先核对目标、输出与评测

用户提出“反复更换单双分支、Mask读出仍不佳，是否有重要问题一直未改正”。本轮只审查代码和已有训练日志/官方PNG，不改模型、监督或官方评测，不启动GPU、训练、重新评分或新作业。

当前判断：没有新证据证明存在一个贯穿所有版本的标签偏移、参数未更新或DDP空跑bug。但已经确认几项会持续影响实验解释的代码行为；其中实例Query职责、训练匹配与输出竞争的一致性，应优先于再次更换头结构。已知工程检查通过不代表目标设计已经合理。

## 1. 几何种子与实例假设的职责没有闭环

当前Unified及直接8维属性版本的Query来自3D超点，数量与局部几何分组有关；`source_many_to_one`按初始来源纯度固定正匹配，每个有支持的Query被监督预测其GT的完整两视图Mask。多个Query可被分配给同一个GT。

术语补充：最新两组实际走的是来源多对一分支，没有调用匈牙利。后文11.28%无正Query统计不能称为匈牙利漏配；普通无硬约束匈牙利在N≥K且无后过滤时会覆盖全部有效GT。完整说明及独立审查交接见`docs/independent_review_handoff_20261018.md`。

最终推理却要产生唯一实例：先同类NMS，再按类别概率乘Membership竞争像素，最后删除获胜面积不足原Mask一半的对象，被删像素保持void、不交给第二候选。训练的独立BCE/Dice没有直接优化这个最终竞争结果。

这并不证明“多对一＋NMS”本身错误；它是常见可用设计之一。但必须证明重复候选能被合并/筛选为一个可靠对象。本项目现有证据反复显示该转化有损失：67390固定heldout raw→最终全GT每图IoU70.02%→54.79%；scene0454_00 raw合格4/4、NMS候选仍4/4、最终只1/4。早期串行、V4双分支也出现原始好Mask到最终输出损失，不能把问题仅归于8维Embedding。

下一次设计前需明确：实例由一个Query负责，还是由多个几何Query协同形成。前者需验证实例选择/去重及正负匹配；后者需有一致的实例合并目标。不能假设换成原型点积或渲染特征后，这个约定自动得到解决。

证据：`tokengs/models/unified_query_loss.py:35`、`:67`；`scripts/export_object_locus_v3_set_official.py:34`、`:49`；完整结果及早期诊断文档。

## 2. 当前背景分类权重的含义与常见每Query加权不同

代码先对全部负Query求分类损失均值，然后整个负组乘0.1；正组则每个已匹配GT为一个平均单位。负Query增加时，背景组总系数不会增加。

若有G个已匹配GT且存在负Query，背景组在该分类聚合中的系数占比为`0.1/(G+0.1)`，不是“每个背景Query权重0.1”。这只是损失权重占比，不是实测梯度占比；无法仅凭系数证明实际优化被哪一项主导。

从67390八rank各最后200更新、1600次窗口曝光统计（非1600独立场景）：

- 平均57.13个Query，平均25.24个正Query；先按窗口计算“正Query数/匹配GT数”再平均为7.77，按GT曝光加权为6.81。两种分母不同，不混用。
- 1598次同时有正GT/负Query的曝光中，背景组系数占比平均仅3.28%。
- 总6685个GT曝光，5931有分类/归属正Query，**754/6685=11.28%没有正Query**。
- 来源关系完全不允许匹配的GT为735/6685=10.99%；它与“最终没有正Query”不是完全相同的统计，不能混用。

这是一项需要重新论证的归一化选择，尚不能命名为已经证明的bug。它尤其可能与动态Query数、重复预测和置信度校准交互，但没有当前对照实验可断言其为AP下降的唯一原因。它也不是早期所有Hungarian版本共有的实现。

来源匹配按初始几何纯度固定，不按最终Mask质量重新分配；无正Query的GT不会得到这条归属/分类正监督。本组渲染Pull/Push仍覆盖这些GT，因此不能说它们完全没有监督；两种监督覆盖的对象职责不同。证据：`SHARED_FAILURE_SUPERVISION_AUDIT.json`、`unified_query_loss.py:9`、`:57`。

## 3. 官方PQ的预测void忽略规则会影响结论

已检查67391实际使用的SIU3R评测环境：`src/evaluator.py`调用`torchmetrics.PanopticQuality`，该版本的`_filter_false_negatives`会忽略预测void覆盖超过一半的未匹配GT；`_calculate_iou`还从union中扣除预测void覆盖GT的部分。

源码位置：`/space/mawb/SIU3R/.venv_gpu_v4/lib/python3.10/site-packages/torchmetrics/functional/detection/_panoptic_quality_common.py:248`及`:254`。这不是本轮导出标签错位或对官方分数进行修改；沿用的是原生固定环境。但它说明留空更多像素与PQ变化可能相关，PQ不是固定全GT召回的替代指标。

2026-10-14诊断已经记录此限制；上一轮67390结果报告应补充这一重要限定。原报告PQ数值仍正确，不能把+0.41个百分点直接当作实例质量收益，也不能未经统计就断言该增益全部由void造成。

本轮从两组完整128场景保存PNG，按同样跨视图拼接、类别/实例编码和原生匹配/忽略条件，统计valid GT上的void覆盖、未匹配且被忽略的GT；不修改或覆盖官方指标。结果归档`SHARED_FAILURE_PNG_AUDIT.json`及本文同名JSON。

完整PNG统计如下；thing GT为每场景跨视图拼接后的唯一实例，context492、target507，非每图GT计数。匹配数依赖原生PQ的扣void IoU，不等于AP的TP。

| 范围/统计 | 原Unified full4 | 直接8维full4 |
|---|---:|---:|
| Context有效GT像素被预测void覆盖 | 5.83% | 7.39% |
| Context被忽略的未匹配thing GT | 53/492 | 45/492 |
| Context原生PQ匹配thing GT | 231/492 | 251/492 |
| Target有效GT像素被预测void覆盖 | 6.36% | 7.61% |
| Target被忽略的未匹配thing GT | 62/507 | 58/507 |
| Target原生PQ匹配thing GT | 228/507 | 245/507 |

**新组void覆盖像素更多，但被忽略的未匹配GT更少；不能据此声称本轮PQ增益是“忽略更多GT”造成的。** 该统计约束了猜测，没有唯一解释AP/PQ分歧。之前“PQ略升”的数值无需改写，但应补充这一评价范围限制。

## 4. 重建基础的退化不能归因于Mask头

同128协议下：旧C PSNR22.5966，原Unified full4为18.0855、full8为18.4225，直接8维full4为18.0470；A双分支full8为19.3692。改变Mask读出或单双分支，没有消除这几组的重建差距。

同时，较早V4隔离组达到23.1940，不能因此宣称冻结Omega/GFM本身不可用，或所有双分支都失败。旧C、新Unified、A/V4的Decoder容量、初始化、特征适配、几何更新和训练配方不同；不能把结果当成单独“分支数量”的结论。

需要核对的基础环节是：同一重建载体在保护理解梯度时的表现、局部几何/相机与Gaussian覆盖、细粒度图像证据是否保留，以及已有预训练/适配收益是否在换架构时丢失。当前只确认PSNR差距和构造不同，没有发现新的坐标或归一化错误。

## 5. 工作流程中需要补上的验收

已有审计充分检查参数更新、初始化、数据身份、真实梯度与DDP同步，这些排除了多种工程空跑。但“有梯度/在更新/探针最佳Mask提高”均不等价于最终实例目标改善。分类/对象存在性与Mask支持不一致、输出竞争损失和排序问题，在10月14日、16日、17日诊断中反复出现，后续结构实验没有用同一组指标证明这些问题已经关闭。

应当先固定当前全量checkpoint与原Unified基线，补齐同128场景的：全GT原始候选覆盖→实际正匹配覆盖→类别/对象存在性资格→NMS→竞争→面积保留；同时核对类别、置信度排序、预测void及完整GT分母。GT辅助类别/排序/读出仅为诊断，不能作为模型成绩。

当前建议：优先诊断目标与输出是否一致；重建可表达性单列；之后只对证据指向的环节做一个受控改动。不要同时改匹配、损失权重、后处理及结构，也不默认恢复旧C预训练权重就必然有效。本轮没有提交这些后续实验。
