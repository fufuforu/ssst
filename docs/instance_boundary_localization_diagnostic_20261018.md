## 已准备的GPU诊断

四个独立worker，各处理一个固定模型的8个相同窗口：67050基线、67128回采、67129边界、67130组合的最终256步检查点，总32模型窗口。13节点4×3090、16CPU/128G、2小时上限。每个worker只加载一个模型，不是训练DDP，无优化器。检查源checkpoint SHA、模型/数据/冻结资产身份、原生模型文件与当时执行快照逐字相同；预测输入RGB和GT与缓存逐值相同。

1. **渲染前特征**：对Gaussian Child特征（实例头之前256维）及实例头输出8维特征，按预测相机/当前Gaussian实际alpha贡献反投影GT，使用贡献纯度≥0.7的thing归属作诊断代理。区分同实例同父Token、同实例不同父Token、不同实例；同时做物理kNN局部对照、全局GT平衡采样和特征对应打乱负对照，记录有效Gaussian/实例数量。它不是实际3D mesh GT，使用两个输入视图GT，结果不能作为原生推理指标。
2. **渲染混合干预**：原8维特征正常混合渲染，对比每个像素取贡献最大的Gaussian特征。最大贡献使用逐段one-hot特征渲染精确求argmax，每一段保留全部Gaussian几何与opacity，不能仅渲染子集改变透射率。验证贡献总和重现原alpha。只改变诊断特征读出，不改任何参数/几何；硬选择不是要直接部署的新输出。
3. **幅值对照**：每个Gaussian的8维向量先单位化，再按原权重渲染，检查embedding幅值是否影响混合。三路均使用相同有效像素集合；另报告最大贡献占比≥0.5、以及7×7覆盖腐蚀（避免空洞/无效邻域产生伪边界）的共同覆盖对照。
4. **几何/读出上界控制**：高纯度GT Gaussian one-hot码（包含两个stuff码）经同一几何渲染，和原特征在同一GT码支持覆盖上比较。它使用GT，只是检查当前几何下理想实例代码能否保留边界，不作为模型成绩。
5. **阈值校准**：只用4train的分数分布选择最大化TPR−FPR的阈值、训练IQR确定温度；分别报告4heldout的AUROC/AP、原/校准权重对比与TPR/FPR。不能凭权重对比增大就宣称有GT边界能力；AUROC、覆盖率、负对照必须一起看。

每个worker第一个窗口先通过同次原生特征重渲染、贡献和=alpha、输入/GT一致等门禁，再继续其余7窗口，不重复第一个模型前向。记录新前向相对旧RGB缓存的最大差异以保留数值告警，不假设跨运行完全确定性。

开始/结束逐张量哈希核实可训练权重不变，并检查全部参数（含冻结资产）版本号不变、无参数grad；没有优化器实例。结束自动CPU汇总，保留小型响应/GT图供可视化，不保存巨大Gaussian×pixel权重矩阵。

## 如何判读

- 若Gaussian 8维在同/异实例间已弱分离，先定位Child特征→8维头是否丢失区分度，以及同实例跨父Token是否不一致；不能仅责怪渲染。
- 若Gaussian可区分，最大贡献图的GT边界能力强于正常混合，支持渲染混合是一个损失来源。两者须在同一像素/覆盖集合比较；3D采样AUROC不能直接减二维AUROC当作平滑幅度。
- 若正常渲染特征AUROC/AP已有清楚区分、原权重对比低、训练校准能改善heldout选择性，则阈值/温度不匹配更可信。
- 若GT one-hot上界也弱或覆盖低，当前Gaussian几何/归属本身可能限制边界，不能把问题仅归于特征头或阈值。
- 多种原因可同时存在；样本是短测4train+4heldout，不是完整模型泛化结论，不预设一定属于单一情况。
