# Full1201 MASt3R encoder freeze comparison

This registered variant reproduces the Full1201 control initialization, immutable scene/window plan, optimizer recipe, loss, schedules, training length, and checkpoints. Its only scientific change is freezing the image encoder in the panoptic understanding branch.

## Freeze boundary

The actual module path is `model.understanding.encoder`, constructed by `PretrainedUnderstanding` in `tokengs/models/object_locus_panoptic_v1_pretrained.py`. The encoder contains `patch_embed`, all 24 `enc_blocks`, and `enc_norm`; its complete named parameter set is frozen after the normal model build and strict pretrained transfer. Its 292 pretrained state entries map from the MASt3R checkpoint keys selected by `patch_embed.`, `enc_blocks.`, and `enc_norm`.

The full concrete parameter-name list, exact source loading keys, tensor count, element count, and initial state digest are recorded in `frozen_encoder_manifest.json` in the experiment report directory. The source key list is the complete 292-entry `LOADED` mapping to `understanding.encoder.*` in `weights_mapping.json`.

The encoder uses `requires_grad_(False)` and remains in eval mode across model `train()` calls. Only the encoder forward runs under `torch.no_grad()`; adapter, pixel decoder, query decoder, panoptic object state and injection, child features, heads, reconstruction encoder/decoder, and anchor geometry remain outside no-grad and trainable. The original raw 24 block outputs are passed to the adapter without a final normalization override.

## Immutable comparison contract

The control's four files are copied byte-for-byte and independently SHA-checked: `weights_provenance.json`, `manifest.json`, `training_plan.json`, and `asset_hashes.json`. Expected provenance is reconstruction step 47500, MASt3R encoder, and epoch 60 panoptic adapter/mask decoder, with strict transfer counts 450/292/187/326.

The plan remains 1191 training scenes from 1201 candidates, 10 zero-candidate scenes, 8337 windows, 1043 updates and 7 padding exposures per epoch, 8 epochs, 8344 updates, and 66752 window exposures. The 56 padding IDs, per-window exposure counts, FP32 AdamW settings, loss and gradient combination, LR groups/schedules, level-embedding zero weight decay, and checkpoints at epochs 0/1/2/4/6/8 are inherited unchanged.

## Verification and deferred evaluation

CPU contracts compare the complete trainable-control and frozen-model state dictionaries after fresh initialization and verify exact optimizer coverage and LR/weight-decay groups. The single-GPU smoke runs one prescribed window through forward, loss, backward, clipping, update, local evaluation, and the single-pair official interface. The eight-GPU smoke runs the first 40 planned global batches and checks rank agreement, finite losses/gradients, active four-layer injection, exposure identities, and encoder immutability.

Training saves checkpoints only. After the user requests evaluation, evaluate dev8 true-novel official AP50 for epochs 0/1/2/4/6/8; choose the highest AP50, breaking ties toward the earlier epoch; run one full `val_pair.json` official evaluation and one fixed val32 evaluation for that checkpoint. Report selected epoch, training time, per-step time, peak memory, and understanding/reconstruction metric differences. Do not add training-instance or area filtering. Do not run the six-checkpoint by six-split matrix, endpoint full evaluations, or text-reference experiments.
